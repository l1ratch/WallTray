# ТЗ: Восстановление редизайна трей-окна (MainWindow.xaml)

## Контекст инцидента

Редизайн трей-окна был спроектирован, реализован, визуально отполирован и явно
одобрен пользователем ("трей окно тепреь прям идеальное визуально!") в этой же
сессии. Позже, в отдельной задаче (удаление Spotlight-кода), ассистент испортил
кодировку файла через PowerShell `Set-Content` без `-Encoding UTF8`, после чего
исправил это через `git checkout -- MainWindow.xaml`. Это откатило файл к
последнему **закоммиченному** состоянию (`03a68be`), которое было ДО всего
редизайна трея — весь несохранённый (не закоммиченный) XAML-код разметки был
потерян без резервной копии.

**Важно**: C#-код (`MainWindow.xaml.cs`, `MainViewModel.cs`) НЕ пострадал —
это отдельные файлы, checkout затронул только `MainWindow.xaml`. Вся бизнес-
логика (свойства, команды, обработчики событий) жива и подключена. Нужно
восстановить ТОЛЬКО XAML-разметку, которая её использует.

## Подтверждение того, что уже жив в коде (не нужно писать заново)

`MainViewModel.cs` содержит (проверено grep, все строки на месте):
- `IsMultipleSourcesEnabled` (`=> Settings.EnableWallhaven`) — определяет режим докера (1 источник vs 2+)
- `IsSingleSourceEnabled` (инверсия)
- `BingNavTabTitle` (`=> IsMultipleSourcesEnabled ? "Bing" : "Главная"`) — динамическое имя кнопки
- `IsStatusPopupOpen` (bool, backing `_isStatusPopupOpen`) — открыт ли попап статуса
- `StatusBadgeText` — текст бейджа в шапке
- `LastCheckStatusText` — текст для попапа (детали последней проверки)
- `ToggleStatusPopupCommand` / `OnToggleStatusPopup()` — переключение попапа по клику
- `GoToSettingsCommand`, `GoToAboutCommand`, `GoToFavoritesCommand`, `GoToGalleryCommand`
- `UpdateCacheStatsAsync()`, `CacheSizeString` — для показа размера кэша в попапе

`MainWindow.xaml.cs` содержит обработчики (строки 174-203):
- `StatusBadge_MouseEnter/MouseLeave` — открывает/закрывает попап при наведении на бейдж
- `StatusPopup_MouseEnter/MouseLeave` — держит попап открытым, если курсор зашёл в сам попап
- `OpenSettingsWindow_Click` — открывает окно параметров

**Значит**: задача — написать/восстановить только XAML в `MainWindow.xaml`,
который биндится к этим уже существующим свойствам/командам и вызывает эти
уже существующие обработчики событий (`MouseEnter="StatusBadge_MouseEnter"` и т.д.).

```
Window.Resources: HeaderButtonStyle, ...(другие существующие стили)
Grid (корневой)

  Row 0 — Шапка:
```

## Целевая структура (что нужно восстановить)

```
Grid (корневой)
  RowDefinitions: Auto (Шапка) / * (Контент) / Auto (Докер навигации) / Auto (Подвал статуса)
                  ^ добавляется НОВАЯ строка Row=2 под докер,
                    старый подвал статуса сдвигается на Row=3

  Row 0 — Шапка (ИЗМЕНЕНА):
    Column 0: кнопка "назад" (условно видна только на странице ImageDetails)
    Column 1: логотип + заголовок страницы + версия
    Column 2: СТАТУС-ВИДЖЕТ (бейдж) вместо старых 3 иконок:
              - маленький Border/Button "бейдж" с иконкой + короткий текст (StatusBadgeText)
              - MouseEnter/MouseLeave -> StatusBadge_MouseEnter/Leave (уже в .xaml.cs)
              - Popup (Placement=Bottom, IsOpen={Binding IsStatusPopupOpen})
                показывает подробности: LastCheckStatusText, StatusMessage,
                IsDownloading индикатор, CacheSizeString
              - сам Popup-контент тоже слушает MouseEnter/Leave
                (StatusPopup_MouseEnter/Leave), чтобы не закрывался при
                переходе курсора с бейджа на попап
    3 старые иконки (Избранное/Настройки/О программе) УБИРАЮТСЯ отсюда —
    их функции переезжают в докер (см. Row 2) и в кнопку "Ещё"

  Row 1 — TabControl: содержимое БЕЗ структурных изменений
    (те же 4 TabItem: Галерея / О программе / Избранное / Детали)
    Полировка вкладки "О программе" и карточек Избранное — см. ниже

  Row 2 — НОВЫЙ нижний докер навигации (динамический таб-бар):
    Grid с ColumnDefinitions, каждая колонка — кнопка стиля DockNavButtonStyle:

    ЕСЛИ IsSingleSourceEnabled (только Bing включён, Wallhaven выключен):
      [ Главная ]  [ Избранное ]  [ Ещё ]
      (кнопка "Главная" использует BingNavTabTitle как текст —
       т.к. по логике ViewModel название динамическое)

    ЕСЛИ IsMultipleSourcesEnabled (Wallhaven тоже включён):
      [ Bing ]  [ Wallhaven ]  [ Избранное ]  [ Ещё ]
      - колонка "Wallhaven" скрывается/показывается через
        ColumnDefinition.Style + DataTrigger на IsMultipleSourcesEnabled
        (ColumnDefinition не поддерживает Visibility напрямую, поэтому
         Width переключается между "*" и "0" через Style.Trigger, ИЛИ
         сама кнопка внутри колонки скрывается через Visibility +
         Converter, а колонка остаётся Width="Auto"/"*" — выбрать один
         подход и быть консистентным)

    Кнопка "Ещё" — открывает Popup/меню с пунктами (используя стиль
    MoreMenuItemStyle для строк меню):
      - "О программе" -> GoToAboutCommand
      - "Настройки" -> GoToSettingsCommand
    (Раньше это была отдельная иконка "Настройки" и отдельная "О программе"
     в шапке — теперь объединены в одну кнопку с попап-меню)

  Row 3 — Подвал статуса (БЕЗ изменений, просто сдвинут с Row=2 на Row=3):
    StatusMessage + LastUpdateText/индикатор загрузки
```

## Новые стили, которые нужно добавить в Window.Resources

1. **`DockNavButtonStyle`** (TargetType="Button")
   - Стиль кнопок нижнего докера
   - Должен визуально отличать активную вкладку от неактивной
     (например через Trigger на IsChecked, если используются ToggleButton,
     или через биндинг Background с конвертером на ActivePage/CurrentSource)
   - Компактный, минималистичный: без лишних теней, аккуратные иконка+текст
     вертикально или иконка+текст горизонтально — на выбор дизайнера,
     ориентир — нижние табы в современных Fluent-приложениях

2. **`MoreMenuItemStyle`** (TargetType="MenuItem" или "Button", в зависимости
   от того, реализуется меню "Ещё" через ContextMenu/Popup+ItemsControl)
   - Строка попап-меню кнопки "Ещё": иконка слева, текст, hover-подсветка

3. **`RoundIconButtonStyle`** (TargetType="Button")
   - Круглые кнопки 32x32 (CornerRadius=16) для карточек Избранного
     (устанавливаемые/открыть в папке/удалить) — единый серый цвет
     `#FFCCCCCC` вместо разноцветных прямоугольных версий, которые
     сейчас в файле (см. текущий MainWindow.xaml:1007-1024 —
     разноцветные Fill="#0078d4"/"#ffd700"/"#ff5555" на прямоугольных
     FluentButtonStyle-кнопках нужно заменить на RoundIconButtonStyle
     с единым нейтральным цветом иконки)

## Новые geometry-иконки (добавить в ресурсы, рядом с существующими Icon*)

- **`IconSun`** — иконка для источника Bing (пример геометрии солнца,
  использовалась в докере/кнопках источников)
- **`IconWave`** — иконка для источника Wallhaven
- **`IconMore`** — три горизонтальные точки (важно: ГОРИЗОНТАЛЬНЫЕ, не
  вертикальные — в чате была явная правка "вертикальные три точки →
  горизонтальные", финальная геометрия была вида
  `M4,12 ... M10,12 ... M16,12 ...` — три круга на одной горизонтальной
  линии y=12, с шагом x≈6)

  Точную числовую геометрию (радиусы, точный Data-path) в истории чата
  найти не удалось в виде готового финального кода — при реализации нужно
  просто нарисовать 3 маленьких круга (Ellipse-геометрия или Path с
  дугами) на одной горизонтальной линии, аналогично стандартной иконке
  "kebab menu" (⋯), но развёрнутой в 90° (было ⋮ вертикально, стало ⋯
  горизонтально).

## Полировка карточек "Избранное" (TabItem 2, ~строки 979-1029 сейчас)

Текущий код (MainWindow.xaml:1007-1024) — 3 прямоугольные кнопки
FluentButtonStyle 32x26 с разноцветными Fill (`#0078d4` монитор,
`#ffd700` папка, `#ff5555` удалить).

Целевое состояние:
- Заменить на `RoundIconButtonStyle`, размер 32x32 (было 32x26 — сделать
  квадратными для правильного круга), CornerRadius=16
- Единый цвет иконок `#FFCCCCCC` (нейтральный серый), без цветовой
  дифференциации по действию — состояние (hover/pressed) даёт фон кнопки,
  не цвет иконки
- Порядок и назначение кнопок остаются те же: Установить обоями /
  Открыть в папке / Удалить из избранного

## Риски и на что обратить внимание

- **ColumnDefinition не поддерживает `Visibility`** — учтено выше,
  использовать либо Width-триггер, либо скрывать содержимое колонки
- При переключении `EnableWallhaven` в настройках докер должен
  перестраиваться реактивно (MainViewModel уже шлёт
  `OnPropertyChanged(nameof(IsMultipleSourcesEnabled))` и
  `OnPropertyChanged(nameof(BingNavTabTitle))` — см. строки 157/159,
  значит биндинг в XAML должен быть на эти же свойства, ничего
  досочинять в ViewModel не нужно)
- Обработчики `StatusBadge_MouseEnter/Leave` и `StatusPopup_MouseEnter/
  Leave` уже есть в `.xaml.cs` — просто подключить их через
  `MouseEnter="StatusBadge_MouseEnter"` и т.п. на нужных элементах,
  НЕ писать новые
