# Варианты реализации установки и автообновления для BingWallTray

Поскольку BingWallTray является легкой фоновой утилитой для Windows (написанной на .NET 8 WPF в виде единого исполняемого файла self-contained), для нее отлично подходят несколько подходов к установке и обновлению. Ниже приведены подробные схемы реализации для каждого варианта.

---

## Вариант 1 (Рекомендованный): Портативная версия + встроенный автоапдейтер
Приложение распространяется как один портативный файл `BingWallTray.App.exe`. Установка не требуется — пользователь просто запускает его из любого удобного места.

### Как работает автообновление:
1. Приложение проверяет наличие новых версий через GitHub API (эта логика уже работает).
2. Если новая версия найдена, пользователю показывается кнопка или диалоговое окно «Скачать и обновить».
3. При нажатии приложение скачивает новую версию исполняемого файла с GitHub (`BingWallTray.App.exe`) во временную директорию (например, в `%TEMP%` под именем `BingWallTray.new.exe`).
4. После успешного скачивания приложение запускает фоновый PowerShell-скрипт (или командную строку `cmd.exe`) с задержкой в 1 секунду и мгновенно завершает свою работу.
5. Запущенный скрипт:
   * Ждет завершения процесса `BingWallTray.App.exe` (по его PID).
   * Удаляет старый исполняемый файл приложения (или переименовывает его в резервную копию `.old`).
   * Перемещает скачанный файл `BingWallTray.new.exe` на место старого файла с именем `BingWallTray.App.exe`.
   * Запускает обновленный `BingWallTray.App.exe`.
   * Удаляет временные файлы и завершает свою работу.

### Плюсы:
* **Простота**: Приложение остается полностью портативным («зеленый софт»), не требующим прав администратора и классической установки.
* **Минимум зависимостей**: Вся логика обновления пишется на чистом C# и встроенном в Windows PowerShell/CMD.
* **Надежность**: Проверенный временем метод, используемый многими портативными утилитами.

### Минусы:
* Нет записи в системном списке «Установка и удаление программ» Windows (хотя для утилит в трее это редко является проблемой).

## Вариант 2: Классический инсталлятор (Inno Setup) + ручное/тихое обновление
Программа поставляется в виде файла установщика `BingWallTraySetup.exe`, который копирует файлы приложения в директорию программ и создает ярлыки в меню «Пуск» и автозагрузке.

### Как работает установка и обновление:
1. Мы пишем простой файл конфигурации `.iss` для компилятора **Inno Setup** (бесплатный инструмент для создания инсталляторов).
2. Скрипт сборки автоматически упаковывает наше приложение в красивый установочный файл.
3. Программа при запуске проверяет обновления. Если обновление доступно:
   * Приложение скачивает файл нового инсталлятора `BingWallTraySetup.exe` во временную папку.
   * Запускает инсталлятор с флагом `/SILENT` или `/VERYSILENT` (для тихой установки) и закрывается.
   * Инсталлятор перезаписывает файлы в папке назначения и автоматически перезапускает программу.

### Плюсы:
* Классический подход (ярлык на рабочем столе, папка в `Program Files` или `AppData/Local/Programs`).
* Возможность чистого удаления через панель управления Windows.

### Минусы:
* Требуется поддержка дополнительного скрипта сборки Inno Setup и установка самого компилятора Inno Setup на машину разработчика.
* Если установить программу в `C:\Program Files`, то для автообновления потребуются права администратора (UAC prompt), либо придется устанавливать ее по умолчанию в локальную папку пользователя `AppData/Local/Programs/BingWallTray`, чтобы избежать запросов прав админа.

## Вариант 3: Использование готового фреймворка (Velopack / Squirrel)
Velopack — это современная библиотека обновления для десктопных приложений на .NET/Rust/C++, являющаяся развитием популярного Squirrel.Windows.

### Как работает:
1. В проект добавляется NuGet-пакет `Velopack`.
2. В коде инициализации приложения прописывается вызов `VelopackApp.Build().Run()`.
3. Сборка и релиз упаковываются с помощью консольной утилиты `vpk`. Она генерирует файлы релизов и дельта-патчи (что позволяет скачивать не весь EXE заново, а только изменившиеся байты).
4. Обновление происходит полностью в фоновом режиме через API библиотеки.

### Плюсы:
* Очень быстрые фоновые обновления («тихий» режим, как в Chrome или Discord).
* Поддержка частичных (дельта) обновлений, что экономит трафик.
* Готовая профессиональная инфраструктура.

### Минусы:
* Добавляет сторонние зависимости в проект и усложняет процесс CI/CD (сборки релизов).
* Дополнительный объем кода в самом приложении.

---

### Резюме и рекомендация:
Если вы хотите сохранить проект максимально легким и портативным (в виде одного EXE-файла), **Вариант 1** является идеальным решением. Мы можем реализовать его без добавления сторонних библиотек прямо в `GitHubUpdateService.cs`. 

Если же вам нужна традиционная установка с ярлыками в пуске и записью в реестр программ Windows, то лучше использовать **Вариант 2** с установкой в `AppData/Local` (без прав админа).
